# example-locker

A Midnight example demonstrating zero-knowledge private state through a locker rental system.

A 4-digit combination is set when renting a locker. Only its hash is stored on-chain. Vacating requires a ZK proof that you know the combination; the digits never appear in any transaction. Vacated lockers are returned to a bank and automatically reused by the next `rent()` call.

## Concepts covered

| Concept | Where |
|---|---|
| `export enum` / `export struct` | `LockerStatus`, `Locker` |
| `export ledger` | `lockers`, `totalLockers`, `lockerBank` |
| `List<T>` | `lockerBank` - dynamic list of available locker IDs |
| `witness` | `myCombination()` - combination bytes, never on-chain |
| `persistentHash` | Commitment pattern - hash stored, digits private |
| `disclose()` | Marks circuit arguments as public |
| Struct spread | `Locker { ...box, status: ... }` - partial struct update |
| Private state | `LockerPrivateState` - combination stored locally |

## Prerequisites

- Node.js >= 20
- [Compact toolchain](https://docs.midnight.network/getting-started/installation#install-compact) (`compact` CLI, version 0.30.0)
- Docker for local devnet or proof server

See [docs.midnight.network/relnotes/support-matrix](https://docs.midnight.network/relnotes/support-matrix) for the full version matrix.

## Quick start (preprod)

```bash
# 1. Start the proof server
docker compose -f proof-server.yml up -d

# 2. Install, compile, and run
npm install
npm run compact
npm run preprod
```

Fund your wallet at [faucet.preprod.midnight.network](https://faucet.preprod.midnight.network/).

## Local devnet (standalone)

Use standalone if preprod is unavailable. It requires [midnight-local-dev](https://github.com/midnight-ntwrk/midnight-local-dev) to be running first:

```bash
# Terminal 1 — start the devnet
git clone https://github.com/midnight-ntwrk/midnight-local-dev
cd midnight-local-dev && docker compose up

# Terminal 2
npm install
npm run compact
npm run standalone
```

The genesis wallet is pre-funded, no faucet needed.

## Troubleshooting

**`could not balance dust`** - the wallet has not yet generated enough DUST to pay transaction fees. Wait a few minutes for DUST to accumulate and try again. DUST generates automatically from registered NIGHT UTXOs but takes time to accrue.

**`SubmissionError: Transaction submission error`** - the transaction failed during submission, usually because the wallet fell out of sync mid-operation. Restart the terminal and run the script again to let the wallet resync before retrying.

**Wallet out of sync generally** - if operations are failing unexpectedly, restarting the terminal is the first thing to try. The wallet syncs from scratch on startup and a fresh session resolves most transient network issues.
